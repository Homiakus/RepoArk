# RepoArk v0.7.0

v0.7 adds a distributed storage/recovery layer without replacing the immutable generation contract introduced in v0.5 and replicated in v0.6.

## Design goals

1. Survive interrupted WAN transfers without restarting multi-gigabyte encrypted copies.
2. Stop treating a heartbeat as evidence that a disk is safe for new placement.
3. Reconcile CAS content without sending a complete object list on every heartbeat.
4. Reduce duplicate immutable-object copies with deterministic placement.
5. Add optional local parity for very large immutable objects without loading an entire object into memory.
6. Give operators a browser recovery path without storing passwords or WebAuthn credentials in RepoArk.
7. Keep point-in-time recovery data-aware: restore only where a verified generation actually exists.

## New packages

- `internal/storagehealth` — capacity + write/fsync/read health probe.
- `internal/objectinventory` — compact 256-segment CAS Merkle inventory.
- `internal/cassync` — verified CAS object archive/install with rendezvous placement.
- `internal/erasure` — block-bounded Reed-Solomon parity/reconstruction.
- `internal/webauth` — OIDC Authorization Code + PKCE, encrypted sessions and RBAC helpers.

## Compatibility

- Config schema: **7**.
- SQL schema marker: **4**.
- v0.6 configuration loads on top of safe v0.7 defaults.
- A v0.6 agent that has not reported storage health remains readable during rolling upgrade, but cannot receive new v0.7 placement or count toward durable quorum.
- Existing direct CLI recovery and generation replication remain available.

See `DISTRIBUTED_STORAGE.md`, `WEB_RECOVERY.md` and `UPGRADE_V0.6_TO_V0.7.md`.
